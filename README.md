# cam-quality-checker

Приложение для автоматической оценки потребительских качеств фотографий,
снятых на разные камеры. Пользователь загружает
одно или несколько фото, приложение считает набор показателей качества,
формирует комплексный балл и строит рейтинг камер.

## Постановка задачи

Существует потребность объективно сравнивать качество фото, получаемых
с разных камер, без лабораторного оборудования и эталонных снимков.
Задача — построить приложение, которое:

1. Принимает одно или несколько фото от пользователя.
2. Автоматически рассчитывает показатели качества изображения.
3. Формирует комплексный балл и рейтинг камер.
4. Устойчиво работает с обычными фотографиями, снятыми на смартфоны.

Ключевое требование: **простота для конечного пользователя**. Не нужно
специальных тест-карт, оборудования или знаний в обработке изображений —
достаточно обычных фото.

---

## Возможности

- Загрузка нескольких фото (JPEG, PNG).
- Автоматическая валидация: отклонение неподходящих снимков с объяснением причины.
- Расчёт 9 показателей качества: резкость, шум, динамический диапазон,
  экспозиция, контраст, насыщенность, цветовой шум, сохранность светов и теней.
- Два метода агрегации: взвешенная сумма и TOPSIS.
- Относительная (min–max по выборке) и абсолютная (относительно эталона) шкалы.
- Настройка весов показателей через интерфейс.
- Визуализация: бар-чарт итоговых баллов, радар-профиль по показателям,
  таблица попарных сравнений.
- Экспорт результатов в CSV.

## Показатели качества

| Показатель | Что измеряет | Направление |
|---|---|---|
| `sharpness` | Резкость (детализация) | больше = лучше |
| `noise` | Яркостный шум | меньше = лучше |
| `dynamic_range` | Динамический диапазон | больше = лучше |
| `exposure` | Точность экспозиции | больше = лучше |
| `contrast` | RMS-контраст | больше = лучше |
| `colorfulness` | Насыщенность | больше = лучше |
| `chroma_noise` | Цветовой шум | меньше = лучше |
| `highlight_rec` | Сохранность светов | больше = лучше |
| `shadow_detail` | Сохранность теней | больше = лучше |

## Методика расчёта

### Приведение к единой базе

Чтобы сравнивать камеры с разным разрешением, все фото уменьшаются
по длинной стороне до **1920 px** (интерполяция `INTER_AREA`). Увеличение
не применяется — оно добавило бы ложную резкость.

**Исключение:** шум оценивается на **оригинале**, потому что уменьшение
усредняет пиксели и «съедает» шум.

### Резкость (Tenengrad)

Градиенты Собеля по X и Y, сумма квадратов градиентов, нормированная
на дисперсию яркости:
S = mean(Gx² + Gy²) / (var(gray) + ε)

Нормировка на дисперсию убирает зависимость от контраста сцены.
`mean` вместо `sum` — зависимость от разрешения.

### Яркостный шум

Изображение разбивается на блоки 32×32. Берутся 10% блоков с наименьшей
дисперсией (предположительно однородные зоны). Усредняется их стандартное
отклонение. Чем меньше — тем лучше.

### Динамический диапазон

Энтропия гистограммы яркости, умноженная на долю не-клиппированных пикселей:
DR = H(hist) · (1 − clip_ratio)
где `clip_ratio` — доля пикселей в диапазонах [0, 5] и [250, 255].

### Точность экспозиции

Отклонение средней яркости от середины диапазона (128):
E = max(0, 1 − |mean(gray) − 128| / 128)

### Контраст

Стандартное отклонение яркости, нормированное на 255:
C = std(gray) / 255

### Насыщенность

rg = |R − G|
yb = |0.5·(R + G) − B|
colorfulness = √(σ²_rg + σ²_yb) + 0.3·√(μ²_rg + μ²_yb)

Хорошо коррелирует с субъективным восприятием «сочности» цвета.

### Цветовой шум

Изображение переводится в LAB. В однородных блоках 32×32 вычисляется
разброс каналов a и b:
chroma_noise = mean_over_flat_blocks(√(var(a) + var(b)))

### Сохранность светов и теней

Берутся верхние (или нижние) 5% пикселей по яркости. В них вычисляется
стандартное отклонение лапласиана — это мера локальной текстуры. Отношение
к средней текстуре по кадру показывает, сохранились ли детали:
ratio = std(Laplacian[mask]) / std(Laplacian[all])
highlight_rec = clip(ratio, 0, 1.5) / 1.5

Значение ~0.5 — нейтраль, > 0.7 — детали сохранены, < 0.3 — света/тени «залиты».

## Методы агрегации

### Взвешенная сумма

Каждый показатель нормируется в диапазон 0–100, затем складывается с весами:
score = Σ wᵢ · norm(metricᵢ)

Два варианта нормировки:
- **относительная** (min–max по выборке) — зависит от того, какие камеры загружены;
- **абсолютная** (относительно эталона) — не зависит от состава выборки.

### TOPSIS

Метод многокритериального принятия решений:

1. Строится матрица решений X (камеры × показатели).
2. Векторная нормировка: `R = X / ||X||`.
3. Взвешивание: `V = R · w`.
4. Определяются идеальное и антиидеальное решения.
5. Вычисляются расстояния до них `d⁺` и `d⁻`.
6. Коэффициент близости: `closeness = d⁻ / (d⁺ + d⁻)`.

TOPSIS не требует выбора единиц измерения, но даёт экстремальные баллы
(близко к 0 и 100), когда одна камера доминирует по всем показателям.

### Веса по умолчанию

| Показатель | Вес |
|---|---|
| Резкость | 0.20 |
| Шум | 0.15 |
| Динамический диапазон | 0.15 |
| Экспозиция | 0.10 |
| Контраст | 0.10 |
| Насыщенность | 0.10 |
| Цветовой шум | 0.08 |
| Сохранность светов | 0.06 |
| Сохранность теней | 0.06 |

Обоснование: резкость — наиболее заметный для пользователя фактор;
шум и DR — технически важные; экспозиция частично корректируется
постобработкой; света и тени — вторичные. В интерфейсе веса настраиваются.

## Валидация изображений

### Жёсткие отказы

| Условие | Причина |
|---|---|
| Короткая сторона < 480 px | Слишком маленькое разрешение |
| Клиппинг > 50% | Сцена неинформативна |
| Лапласиан < 10 | Нет текстур — резкость не оценить |
| Мало однородных блоков | Невозможно оценить шум |

### Мягкие предупреждения

| Условие | Предупреждение |
|---|---|
| Длинная сторона < 1920 px | Оценка резкости может быть менее точной |
| Клиппинг > 30% | Динамический диапазон занижен |
| Формат HEIC/HEIF | Возможен пересжатый оригинал |

## Установка и запуск

### Требования

- Docker Desktop (Windows, macOS) или Docker Engine (Linux).
  Инструкция: https://www.docker.com/products/docker-sandboxes/#get-started
- Свободный порт 8501.

### Запуск через Docker Compose

1. Перейти в директорию приложения:
   ```
   cd /path/cam-quality-checker
   ```
2. Собрать и запустить контейнер:
   ```
   docker-compose up --build
   ```
3. Открыть в браузере:
   ```
   http://localhost:8501
   ```
4. Для остановки — `Ctrl+C`, затем:
   ```
   docker-compose down
   ```

### Запуск через Docker

```
docker build -t camera-rank .
docker run --rm -p 8501:8501 camera-rank
```

### Локальный запуск без Docker (для разработки)

```
git clone git@github.com:MatveyMahlyshev/cam-quality-checker.git
cd cam-quality-checker
uv sync
uv run streamlit run main.py
```

## Как пользоваться

1. **Подготовьте фото.** Снимайте одну и ту же сцену разными камерами,
   при одинаковом освещении, без цифрового зума. В кадре должны быть
   и текстуры (листва, кирпич, текст), и ровные участки (стена, небо).

2. **Загрузите фото в приложение.** Можно несколько сразу. Каждому
   присвойте название камеры.

3. **Проверьте результат валидации.** Если фото отклонено — прочитайте
   причину. Если есть предупреждения — оцените, критично ли это для вашей
   задачи.

4. **Настройте параметры.** Выберите метод агрегации (взвешенная сумма
   или TOPSIS). При необходимости настройте веса показателей. Переключите
   шкалу (относительная или абсолютная).

5. **Изучите результаты.** Итоговая таблица, бар-чарт баллов, радар-профиль
   по показателям, таблица попарных сравнений.

6. **Экспортируйте CSV**, если нужно сохранить результат.

## Ограничения

1. **Относительность балла при min–max.** Балл зависит от состава выборки.
   Для устойчивого результата используйте абсолютную шкалу или загружайте
   не менее пяти камер.

2. **Зависимость от сцены.** Резкость, динамический диапазон и экспозиция
   оцениваются корректно только на подходящей сцене (текстуры + средний
   контраст).

3. **TOPSIS даёт экстремальные значения.** При доминировании одной камеры
   балл стремится к 100, аутсайдер — к 0.

4. **Шум оценивается по однородным блокам.** На текстурированных сценах
   оценка может быть завышена.

5. **Нет калибровки по эталону.** Абсолютная шкала использует условный
   эталон, заданный экспертно. Не заменяет лабораторные измерения.

6. **Один снимок ≠ вся камера.** Оценка по одному фото отражает конкретный
   кадр, а не камеру в целом. Для устойчивой оценки нужно несколько фото
   разных сцен.

## Обоснование методики

**Резкость** — наиболее заметный потребителю фактор. Существуют
безэталонные методы с корреляцией Спирмена до 0.99 с субъективными
оценками (сравнение 28 метрик резкости).

**Шум** критичен при слабом освещении и хорошо различает классы камер.
Оценка по однородным блокам — стандартный безэталонный подход.

**Динамический диапазон и экспозиция** определяют, насколько правильно
камера передаёт яркость сцены. Оцениваются через гистограмму.

**Цветовые показатели.** Насыщенность по Hasler & Süsstrunk (2003)
хорошо коррелирует с восприятием «сочности». Цветовой шум — признак
плохой обработки в LAB-каналах.

**Света и тени.** Современные смартфоны активно применяют HDR, и сохранность
деталей в крайних зонах яркости отличает камеры среднего и высокого класса.

**Методы агрегации.** Взвешенная сумма прозрачна, интерпретируема и легко
настраивается. TOPSIS — стандартный метод многокритериального выбора,
не требует выбора единиц измерения и даёт устойчивый рейтинг при большом
числе критериев.
